Status Note:
- This document defines the target schema and runtime rules.
- The current engine implements a subset. See docs/PRODUCTION_PROGRESS.md for status.

- 1. Global Architecture Rules
- [Critical] The mobile architecture must use a hybrid schema: high-level functional sections plus a small layout primitive set.
- [Critical] The allowed core layout primitive set is container, column, row, stack, spacer, and scroll.
- [Critical] The data-binding model must be hybrid between inline authored content and typed runtime sources.
- [Critical] Commerce blocks must be source-driven through typed data references.
- [Critical] Content blocks must keep inline authored content.
- [Critical] Web JSON must remain unchanged.
- [Critical] Mobile JSON must be generated through a pure transform layer.
- [Critical] The transform contract is Web JSON input to Mobile JSON output.
- [Critical] Transform execution must be deterministic.
- [Critical] Transform execution must be stateless.
- [Critical] One web page input must produce exactly one mobile page output.
- Transform must be runnable at publish time.
- Transform must be runnable inside editor preview flow.
- [Critical] The runtime must have a single WidgetRegistry keyed by node type.
- [Critical] The runtime must have a single ActionDispatcher.
- [Critical] The runtime must have a single DataResolver.
- Builder changes must stay minimal.
- Mobile support must be added without introducing a separate mobile authoring system.
- [Critical] The architecture version is locked to schemaVersion 1.0.
- JSON schema definition must be formalized and used for validation.
- Schema validation must be used in CI.
- Schema validation must be used in engine load path.
- [Implicit] Mobile and web outputs must coexist as parallel publish artifacts.
- [Implicit] Type names are the ABI between JSON and Flutter widget construction.
- [Implicit] The transform is the only allowed adaptation boundary between web and mobile semantics.

- 13. Implicit Design Decisions
- [Implicit] [Critical] The mobile schema is intentionally constrained and not a full mirror of web capabilities.
- [Implicit] [Critical] Transform is the sole authority for platform adaptation.
- [Implicit] [Critical] Runtime execution is declarative from JSON and centralized through registry/dispatcher/resolver services.
- [Implicit] Stable ids are required for transform determinism, cache stability, and node identity continuity.
- [Implicit] Vertical-first UX is prioritized over preserving desktop-like composition.
- [Implicit] Data freshness is prioritized over publish-time embedded catalog snapshots.
- [Implicit] Enum-based contracts are preferred over open-ended configuration.
- [Implicit] Preview must validate transform output fidelity before publish.
- [Implicit] Functional blocks exist because CSS translation cannot reliably recreate domain widgets on mobile.
- [Implicit] One registry/dispatcher/resolver architecture minimizes divergent behavior paths.
- [Implicit] Sliver-first page composition assumes long, scroll-heavy mobile pages.
- [Implicit] Theme is treated as application infrastructure, not per-widget ad hoc styling.
- [Implicit] Cache keys and template grammar are intentionally narrow to guarantee predictability.
- [Implicit] Optional mobile hints intentionally provide limited override power.
- [Implicit] Mobile and web artifacts are intended to be published together.
- [Implicit] Golden transform snapshots are required to lock deterministic output behavior.
- [Implicit] Flutter widget tests are required to catch visual regressions from schema/transform changes.
- [Implicit] The system is designed for extension by adding new registry node builders and DataResolver source cases only.
